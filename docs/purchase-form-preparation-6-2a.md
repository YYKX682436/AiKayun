# ⑥-2A 本地填写模板与私有草稿基础

> 历史阶段文档：⑥-2A 仅交付准备能力。正式顾客填写、购物车与成交快照已在[⑥-2C-1](./purchase-forms-6-2c-1.md)接通；本文件中“前台尚未开放”的说明仅描述 ⑥-2A 完成时的状态。

## 阶段范围与业务规则

⑥-2A为购买填写准备本地模板、不可变版本、商品/SKU准备关联、加密草稿和私有图片对象。模板冻结和关联都只是后台准备配置，不代表顾客购买已启用。本阶段没有开放顾客填写、上传、购物车或结算入口，也没有改动卡易信只读销售限制。

一行购买资料以后对应该行全部数量；有效内容相同的同 SKU、同模板版本资料才可合并，不同账号、区服、图片或其他值保留独立行。下单前允许修改草稿并重新校验报价。订单创建后由不可变成交快照负责解释原资料；未付款填错应取消并重下，已付款走售后，已提交或结果未知的采购不能编辑后重发。以上与订单、购物车及采购幂等接入留到⑥-2B/C。

## 复用与最小数据模型

- `packages/contracts/src/purchase-forms.ts` 定义独立的本地契约，不把卡易信数字类型当作本地协议，也不解释或执行上游正则、脚本和公式。
- 后台编辑复用管理员会话、CSRF、商品行锁和 `expectedRevision`。商品/SKU继续使用当前商品与 SKU 身份，不改变价格、库存、可售状态或履约资格。
- 顾客草稿复用现有顾客会话和游客订单 HttpOnly 会话。服务层从已认证主体读取顾客 ID/会话 ID，游客以服务端解析的游客 token 哈希定位会话；数据库以 `num_nonnulls(customer_id, guest_order_session_id) = 1` 保证所有者互斥。
- 草稿密文以现有 `PAYMENT_CREDENTIAL_KEY_RING` 中的密钥版本为根，通过独立 HMAC 用途字符串派生购买草稿密钥，再以 AES-256-GCM 加密。AAD 绑定草稿 UUID；行记录 nonce、tag 和 key ID。新密文不复用支付/供应商/交付密文格式。保留历史 key ID 对应密钥才可解密；缺失密钥、认证失败或解码失败一律报错，不以空资料覆盖。
- 图片使用 `PRIVATE_FILE_ROOT/purchase-attachments/{staging,objects}`，与数字商品私有文件处于同一已持久化卷、不同命名空间。旧 `private-files:check/repair` 只管理 `private_file_objects`，不会扫描购买附件；`purchase-drafts:check/repair` 只管理购买附件行及子目录，不管理旧交付对象。

阶段基础迁移为 `202610240002_purchase_forms_drafts`，新增：

| 对象 | 作用 |
| --- | --- |
| `purchase_form_templates` | 可编辑工作定义、修订号和当前版本计数 |
| `purchase_form_template_versions` | 内容摘要及冻结定义；数据库触发器拒绝 UPDATE/DELETE |
| `purchase_form_template_identities` | 永不复用的字段/选项 UUID、业务含义、类型和父身份登记 |
| `product_purchase_form_settings` | 商品默认模式：`none` 或 `template`；没有行表示 `not_configured` |
| `sku_purchase_form_overrides` | SKU显式覆盖；没有行表示继承商品默认，`none` 明确不使用模板 |
| `purchase_form_audit_events` | 只记录管理员操作及非敏感摘要，不保存填写正文 |
| `purchase_drafts` | 版本固定、修订受控、30天有效期的加密私有草稿；含单向认领来源 |
| `purchase_draft_attachments` / `purchase_draft_attachment_references` | 上传状态、私有对象元数据、字段归属和有效引用 |

模板字段和选项 UUID 是身份；标题、提示和顺序可编辑。字段业务含义、类型、所属级联分支改变时须新建身份；身份登记不可删除或改写。冻结版本由管理员行锁、`expectedRevision` 和版本唯一约束生成，旧版本不变且保留可读；SKU/商品准备关联以外键 `ON DELETE RESTRICT` 固定引用版本。数据库触发器拒绝直接 SQL 对冻结版本、身份登记和审计历史执行 `UPDATE`、`DELETE` 或 `TRUNCATE`。

R1前向迁移 `202610240003_purchase_form_audit_product_identity` 仅移除准备操作审计对商品/SKU的外键；审计中的原始 UUID、内容摘要及不可变约束继续保留。既有安全删除流程先执行订单、库存、卡密、履约及其他历史保护，再在同一事务内清除普通商品/SKU准备关联。冻结模板版本和审计记录不删除；迁移不改写已应用迁移或历史数据。

## 模板结构、规范化与资源限制

本地字段类型为单行文本、多行文本、数字字符、单项选择、级联选择/分支扩展字段和私有图片；每个字段都有明确 `required`。校验先执行有界迭代检查，再进行字段/选项结构检查，避免未受限递归。级联子节点不得越过最大深度。准备中上游未知必填性不映射为本地选填；本轮没有上游导入/映射。

规范化版本为 `1`，摘要由服务端以 `normalizationVersion + templateVersionId + normalizedValues` 的规范 JSON 计算。对象键排序，数组顺序保留；数字字符按字符串校验和保留，账号前导零、大小写及有意义空白不变。CRLF/CR 统一为 LF；不对所有文本 trim。空字符串、null、缺失值在有效内容中统一为未填写并省略；完整性检查单独执行。选择值保存稳定选项 UUID；级联路径有序，路径必须是定义中的真实分支，所有提交的扩展值都必须属于当前活动分支。图片值只含稳定附件 UUID，不含签名 URL、临时 URL、随机 draft ID、读取时间或客户端摘要。

本轮统一上限如下；超过限制明确拒绝，不截断：

| 项目 | 上限 |
| --- | ---: |
| 模板定义 / JSON请求体 | 48 KiB / 64 KiB |
| 顶层字段 / 含级联扩展字段总数 | 30 / 60 |
| 单层子选项 / 级联整树节点 / 最大深度 | 20 / 200 / 5 |
| 字段/选项标题 / `meaningKey` / 占位提示 / 帮助文本 | 120 / 64 / 180 / 240字符 |
| 单个文本值 / 所有文本值总和 | 4,000 / 16,000字符 |
| 每主体草稿数 / 单草稿图片数 | 50 / 10 |
| 单图 / 单草稿图片总量 | 5 MiB / 20 MiB |
| 每主体图片数 / 总量 | 100 / 100 MiB |
| 未来 multipart 请求体上限 | 5 MiB + 32 KiB |
| 图片边长 / 像素 | 8,192 / 16,000,000 |

单字段图片数还受模板 `maxCount`（1～3）约束。服务端仅接受 JPEG、PNG、WebP 声明；Sharp 检查实际解码格式与声明一致、单帧、完整解码、尺寸和像素上限，再统一转成 WebP。并发解码最多 2 个。请求流原始字节和输出文件均限制 5 MiB；未来 multipart body 上限常量为 5 MiB + 32 KiB。由于本轮没有上传路由，该 HTTP 上限尚未应用；⑥-2B接入时须通过路由级 bodyLimit 实施，不得扩大 Fastify 全局 64 KiB JSON bodyLimit。不抓取远程 URL，也不向供应商上传图片。

保存草稿校验字段归属、值类型、可用选项、当前活动分支、附件所有权、正文大小与配额，但允许不完整；显式完整性检查另行返回稳定字段 UUID。错误只返回字段 UUID 和错误码，不包含顾客填写原文。任何客户端摘要都不可信。

## 身份、生命周期与认领

草稿从创建时固定引用一个不可变模板版本，后续模板更名或改版不重新解释旧草稿。服务操作在同一数据库事务内重新核验顾客为有效状态、当前会话未撤销且未过期；游客会话也逐次检查撤销和到期。写入按顾客/游客主体锁定，并以草稿 ID、修订号及归属条件读取；归属不符统一视为不存在。已登录顾客校验失败不回退到游客身份。

草稿最多保留 30 天。保存和读取不延长期限；显式续期且修订一致时重新设为 30 天。草稿 ID、附件 ID、摘要都不是访问凭据。正文不进 URL、日志、审计、公共响应或缓存；授权读取才返回必要正文。数据库中的正文是密文，API logger 对请求体整体脱敏。Web端不把原始填写值用于浏览器存储键名。

`claimGuestPurchaseDrafts` 是⑥-2B可调用的窄范围原语：同一事务核验当前顾客与原游客会话，逐个锁定用户指定的未过期游客草稿，检查顾客容量后把草稿及附件所有权原子改为当前顾客。创建与认领统一锁定主体容量行并重新统计有效草稿；认领容量按真正新增的草稿计算，批次容量不足整体回滚，重放不重复占额。数据库仅允许一次 guest→customer 转移并记录原游客会话；相同顾客和会话重放幂等，原游客及其他顾客之后都不能接管。它不迁移订单、钱包、购物车或其他游客记录，也不自动认领本机全部草稿。

## 附件落盘、读取与清理恢复

附件先在数据库登记 `uploading` 与保留配额，随后完成流读取、格式/图片校验、临时文件 fsync、不可覆盖链接发布及目录 fsync，最后再次锁定并核验会话、草稿修订、字段活动状态与配额，然后转为 `ready`。上传期间草稿失效、归属改变、修订变化或字段不可用，不能返回成功；已确定的失效在草稿/附件锁下条件释放未引用 `uploading` 占位，文件删除失败则保留 `deleting` 供修复器重试。提交结果未知时保留记录和文件，清理器按状态及引用恢复，不把“文件已落盘”单独当作结果未知。文件内容不原地替换，替换生成新 UUID。

保存正文时锁定草稿和附件并原子更新引用；数据库引用触发器只接受当前有效草稿的 `ready` 附件且字段 UUID 相同。已引用图片必须先从草稿值中移除，再请求删除。读取每次重新授权并比较磁盘大小/SHA-256；对象无公开路由和永久 URL，不返回磁盘路径。响应接入时须使用 `private, no-store`、`nosniff` 等私有内容头。

`purchase-drafts:repair` 的候选查询只负责筛选。清理到期草稿时取得草稿锁后重查当前状态和 `expires_at`；旧 `ready` 附件另重查创建时间宽限、状态与引用关系。若续期先提交，清理跳过仍有效草稿的图片；若清理先把草稿置为失效，后续续期明确失败。清理锁顺序仍为草稿再附件；待删对象可重复修复。

执行：

```sh
pnpm --filter @aikayun/api purchase-drafts:check
pnpm --filter @aikayun/api purchase-drafts:repair
```

检查只输出计数。修复器按到期草稿、失败/中断上传、待删除附件和无有效引用对象分批处理，最多每批 500；清理对象需经过 24 小时宽限、数据库状态/引用核对与锁定。重复修复安全。旧清理器不检查 `purchase-attachments`，新清理器不扫描旧 `objects/`/`staging`。

当前 `scripts/backup-compose-data.sh` 在同一静止窗口备份 PostgreSQL、公开媒体、整个 `PRIVATE_FILE_ROOT` 和独立 `INSTANCE_IDENTITY_ROOT`，v3 清单校验四个归档的 SHA-256。身份归档含 PKCS#8 实例私钥，备份必须静态加密并由部署环境单独托管解密材料。`scripts/restore-test-compose-data.sh` 仅允许明确的隔离测试 Compose 项目、`_test` 数据库及同一 v3 身份归档。恢复验收应从代表性数据库样本和 private-file 根目录副本恢复到隔离副本，并比较模板版本、草稿身份/修订、附件关系和附件 SHA-256。卷与备份静态加密仍由部署环境负责。

## 后台准备界面及启用隔离

管理员在“购买填写模板”页编辑工作定义、选择/级联/分支扩展字段及真实预览，并可保存草稿、冻结版本和查看历史版本。商品详情页可设置商品默认模板或明确不使用；SKU可继承、明确不使用或引用固定版本。预览复用同一字段和规范化组件，图片上传在预览中明确禁用。预览只使用管理员定义/样本，不读取顾客资料。

界面使用“准备配置，尚未应用到顾客购买”“保存为准备配置版本”等文案，没有发布或启用购买表单按钮。模板API仅为管理员路由；没有公开模板读取、顾客草稿读写、顾客上传或附件读取路由，知道版本/草稿/附件 UUID不能获得访问权。公共商品响应也不带准备模板关联或顾客填写资料。商品和SKU的价格、库存、履约与可售校验保持原样；本轮的旧商品报价和订单仍走原路径。

## 后续接入约定与不在本阶段的内容

⑥-2B接入现有购物车分行、服务端内容身份合并、报价和订单成交快照/幂等边界，并按稳定锁序绑定附件引用；同 SKU 不同有效填写内容保留独立购买行，行内一组填写资料作用于该行全部数量。登录只认领明确指定的草稿。订单长期附件归档、售后展示及交易规则变更另行设计验收。

⑥-2C负责正式顾客/游客填写流程、前后台闭环及供应商字段对应准备；购买入口只有在交易链路接通并明确启用后才可开放。本阶段不注册相关公开路由。

⑥-4负责真实供应商采购、查单及未知结果恢复。采购一旦提交或结果未知，必须保留原资料和原操作证据。⑥-5负责回调、上游退款及关联售后。现有 `http_json_v1` 语义、订单快照、履约恢复和卡易信只读资格不在本轮改动。

本阶段没有改购物车主键、订单 SKU 唯一约束、库存/限购跨行聚合、旧游客购物车/待确认批次格式、checkout导航或提交方式；没有实现上游字段映射、自动定价、成本/利润保护、卡易信采购/上传、供货 API、支付或退款改造。真实商户认证、账户/商品读取和采购依然 NOT_VERIFIED/未实现；正式购买填写全链路未开放。
