## 结论及证据分级

**尚不能识别经授权的目标商户，也不能建立真实商户只读实证或关闭采购协议缺口。** 本轮没有向任何商户发送账户、商品、查单、采购或退款请求，没有使用真实凭据、部署或修改业务代码。目标 HTTPS 地址、目标部署的 V3 版本、连接及凭据版本、可用授权范围和安全测试配置均为 **NOT_VERIFIED**。不能选择历史候选域名代替目标。

证据分为以下几类，不得互相升级：

1. **源码事实**：固定基线中的本地实现与限制，只证明本商城的行为。
2. **官方协议历史记录**：⑥-4A 于 2026-10-27 记录曾正常访问卡易信《商家客户 API 3.0》各页后的原文要点及冲突。本轮网页检索工具无法打开这些页面，尝试浏览器访问也超时，因此本轮未重新核验原文或其现行版本；下文标为“⑥-4A 的官方协议历史记录”，不是本轮直接取得的新原文。其适用于哪个目标商户和部署版本仍未证明。原始链接及逐项历史摘录见 [⑥-4A](kayixin-procurement-investigation-6-4a.md#协议证据矩阵)。
3. **目标商户只读实测**：本轮无；三个固定接口均 **NOT_RUN**。历史候选站点的无凭据认证错误及合成夹具成功不构成目标实测。
4. **供应商书面确认**：本轮在仓库阶段文档中未发现绑定目标商户及版本的书面回复；外部渠道是否存在未核实。未发送联系或询价消息。
5. **NOT_VERIFIED**：尚缺可归属、可追溯证据的目标身份、协议或运行行为；不能以字段名、HTTP 状态、夹具、历史其他商户或本地策略代替。

## 目标识别与只读联调准备

- 用户本轮未指定商户 HTTPS 地址或现有连接身份。仓库根环境配置的键名检查未发现独立指定目标商户或 V3 凭据的配置键；没有输出或记录配置值。当前运行的 Compose `db` 服务所选**一个数据库**，在只读事务检查全部非系统 schema 后没有 `supplier_connections` relation。该检查不涉及其他本地数据库、远程环境或生产环境，不能推断它们没有配置，也不能证明不存在授权凭据。
- [⑥-1](supplier-kayixin-v3-readonly.md#站点核实与-not_verified) 记载三个历史候选在 2026-10-24 的无凭据探测，仅证明当时认证错误；既不证明归属用户，也不证明真实认证成功。本轮没有选择或访问这些候选站点。阶段文档没有给出可确认的目标连接版本或授权范围。
- 要取得只读证据，需先由用户明确目标 HTTPS 站点及归属，或提供可独立核实归属的现有配置入口；确定适用软件/API 版本、连接配置版本和对应凭据版本、账户对三个接口的只读授权，以及安全测试环境和可核对的商品 ID。凭据应仅通过现有受保护部署配置提供，不写入聊天、报告、仓库或终端日志；配置存在也不能自行推断已获读取授权。
- 条件齐备后才可逐项执行 `POST /api/v3/user/getAccount`、`POST /api/v3/goods/getList`、`POST /api/v3/goods/getDetail`，记录目标身份、版本、时间、每项实际执行与结果的脱敏摘要；空列表不能算详情成功。单次读取只说明该时点的账户或商品观察，不能证明交易语义。现有连接测试会向本地数据库写测试及审计记录；如果要求数据库也严格只读，应评估现有单独目录读取路径及其副作用，不把测试按钮误称为无本地写入。

## 固定基线源码事实

- [只读读取器](../apps/api/src/commerce/kayixin-customer-v3.ts) 固定三个业务路径，V3 用最终 UTF-8 正文字节签名和传输，账户正文为空；源码签名为 `MD5(AppID + AppSecret + "3.0" + timestamp + bodyJson)`。请求上限 16 KiB，账户、列表、详情响应上限分别为 64 KiB、1 MiB、2 MiB。它不实现采购、退款或任意上游路径。与 ⑥-4A 的签名规则历史记录相对应，但目标认证仍未实测。
- [安全传输](../apps/api/src/commerce/supplier-http.ts) 对正式地址要求 HTTPS 站点根、检查全部 DNS 答案并固定地址、验证 TLS、禁止重定向，设置 8 秒总超时及有界收发；仅受控测试环境存在本机例外。[连接管理](../apps/api/src/catalog/admin-supplier-connections.ts) 使用连接、配置与凭据历史版本，返回前复核当前配置；[凭据加密](../apps/api/src/commerce/supplier-api-crypto.ts) 将密文绑定协议、连接和凭据版本。本地保留历史密钥并不证明上游允许轮换后查旧单。原响应、凭据、签名、购买资料不得写入日志。
- [商品读取器](../apps/api/src/commerce/kayixin-customer-v3.ts) 将参考报价保留为十进制字符串，`currency=null`、`actualDebitVerified=false`；数量规则校验后保留且 `conversionVerified=false`，未进行单位换算，商品 `procurementReady=false`。库存和参考报价只是时点观察，不能推导结算币种、采购单位或扣费上限。
- [审核映射管理](../apps/api/src/catalog/admin-supplier-product-mappings.ts) 和 [映射契约](../packages/contracts/src/supplier-product-mappings.ts) 核验商品/SKU、字段与结构，并对异步报价返回复核来源。结构指纹不包含数量规则和报价；预览是合成内部表示，不是上游请求体。真实数量、费用规则、实际扣费和字段编码不能由 reviewed 映射或参考报价推断。
- [来源选择器](../apps/api/src/commerce/procurement-source-selection.ts) 在生产固定返回空集合；[只读迁移](../apps/api/src/db/migrations/202610240001_kayixin_readonly.ts) 和 API 门禁继续禁止卡易信取得旧协议销售/履约资格。⑥-4B 的冻结来源、操作及单位身份只可通过隔离测试来源建立；已有历史订单不会自动绑定当前映射。详见 [⑥-4B-1](kayixin-procurement-identity-6-4b-1.md)。
- [执行器](../apps/api/src/commerce/procurement-executor.ts) 的传输类型明确仅供夹具，无生产传输或调度器；`local-procurement` 身份不是已验证的 `outerNumber`。准备时绑定单位、币种和最大风险；发送意图最多一次，超时、租约过期或未知结果只查原身份，负查单不能触发重发或风险释放。供应商号冲突和不明身份转人工；已知单号查不到通常转人工，已经持久成功待交付的状态按现有规则保留，负查不能证明未执行。成功、可交付与扣费是不同证据；迟到事实尽力追加而不覆盖有效代际，但持续数据库故障可能使其未能持久化，原身份和风险仍须保留。参见 [⑥-4B-2](kayixin-procurement-execution-6-4b-2.md)。
- [风险预算](../apps/api/src/commerce/procurement-risk-budget.ts) 当前只支持合成 `TST`；每日新增额度与跨日未核销风险分开，本地预留不保证供应商不会超扣。付款、退款和交付保护及冲突事实继续生效。真实 SIGKILL 和数据库/私有卷恢复是 [⑥-4B-3](kayixin-procurement-execution-6-4b-3.md) 中的隔离夹具证据，不证明目标商户或生产灾备。

## 对齐执行内核与适配器职责

可复用经审核的本地订单及支付/退款锁、购买资料和私有附件归档、版本引用、操作 UUID 和本地单位分配、请求意图、租约代际、只追加事实、风险预算模式、原逐单位交付和 SIGKILL 恢复测试方法。使用前仍须确认现有隔离路径适用范围；来源选择器和生产资格保持关闭。

未来 V3 适配器必须独立承担：绑定目标商户、配置及凭据历史版本；依据经确认的数量和费用规则确定并冻结采购批次、本地单位分配、字段资料及最大风险；按照目标协议严格编码签名、商品/SKU、`attach` 和图片；建立本地身份到 `outerNumber` 的有证据映射及原单查询；验证响应归属、身份和金额，保留上游原状态与脱敏/加密证据，区分接受、待处理、未知、明确未执行、部分可交付、扣费与退款事实。不得把夹具 DTO 或 synthetic success 直接当 V3 结果。

## ⑥-4C-2 阻断条件及未来正式联调最小范围

**进入真实协议适配器开发的阻断**：首先明确目标身份、HTTPS 和部署/API/连接版本与授权；取得可追溯、适用该商户的协议原文及书面解释，解决上表对拟支持商品和功能所必需的币种、数量、费用、强制扣费上限、身份及查单、状态和资料编码缺口；明确安全失败分类、历史凭据查询和人工对账流程。缺失项不能通过猜测实现，未获覆盖的字段/商品须明确拒绝。真实币种风险预算、冻结规则与服务器约束、付款/退款竞争、冲突/迟到事实、私有资料处理，以及生产恢复/备份要求须形成可审查设计及隔离验证计划。只读认证成功不自动允许写适配器或真实采购。

**未来正式联调的最小范围，需另行明确授权**：专用隔离商户及低余额、确定的目标版本和受限凭据、独立测试商品与非真实顾客测试资料、明确批准的金额上限/次数/时间窗口、负责人和立即停止机制、可核对的上游订单及余额/费用账单、未知结果人工处置与恢复方案；先通过无真实扣费的协议夹具及并发、预算、退款保护、迟到响应和 SIGKILL 回归，再按单独批准的范围逐步核对数量、实际扣款、状态与原身份查询。任何重发、退款或图片测试均需明确的专项范围和授权；不能利用一次负查单或一次成功证明一般幂等或一致性。生产数据库与私有卷一致备份、恢复能力及真实商户行为尚未验证，不能以隔离恢复结果替代。
