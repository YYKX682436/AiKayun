# ⑥-3B 供货成本观察、变化比较及安全确认

## 范围与基线

本阶段基于固定基线 `220ec9bf2b5ea9077632dc9d6f89f558471a0980`，完成管理员主动读取卡易信 V3 参考报价、受限保存观察历史、人工确认内部 CNY 单位成本，以及与既有 ⑥-3A 定价预览的交接。没有实施真实采购、自动调价、定时任务或 ⑥-3C。

实现前复核了 `docs/pricing-rules-6-3a.md`、`docs/purchase-product-mappings-6-2c-2.md`、`docs/supplier-kayixin-v3-readonly.md`，并检查 ⑥-2 的商品/SKU 修订、订单快照、既有价格 API、供应商连接版本和结构漂移保护。

## 权威金额与边界

- `product_variants.cost_price` 仍是本店唯一有效的内部 CNY 单位成本，只有管理员明确确认的人工录入可以更新它。
- `product_variants.sale_price` 仍是唯一成交售价。成本观察和成本预览不修改 `sale_price` 或 `compare_at_price`。
- 卡易信 `quote.amount` 只作为未经验证的上游参考报价。保存值保持原始十进制字符串；`currency` 为 `null`、币种状态为 `unspecified`、单位为 `unverified`、`actualDebitVerified` 为 `false`，报价依据为 `upstream_account_reference`。
- 人工 CNY 成本确认只代表管理员录入了内部单位成本，不表示卡易信实际扣费、结算币种或数量换算已经核实。参考报价及其数值差不参与内部成本公式。

## 管理员报价观察与历史

管理员可在供应商商品映射页为所选本地 SKU 主动点击“读取当前映射报价”。服务端只复用既有卡易信 V3 商品详情只读调用；顾客访问、商品展示、结账报价和下单均不触发供应商请求。

新增管理员接口：

- `POST /api/v1/admin/products/:id/variants/:variantId/reference-quotes/observe`：按商品、SKU 和映射修订读取并保存一次观察；管理员会话和 CSRF 校验必需。
- `GET /api/v1/admin/products/:id/variants/:variantId/reference-quotes`：读取该 SKU 最近最多 50 条记录；顾客会话不能访问。

`supplier_reference_quote_observations` 记录本地商品/SKU、管理员、审核映射 ID/修订/版本/状态、供应商连接及配置版本、上游商品/SKU 身份和规格组合、报价范围、原始报价、来源读取时间、本地观察时间、结构指纹、失败状态和可比性。记录不可更新；每个本地 SKU 的保留历史上限为 50 条，删除仅用于窗口外历史清理。

只有前次和本次都取得报价，且连接、配置版本、上游商品、SKU 类型/编码/组合、报价范围和结构指纹全部一致时，才计算原始报价数值差。差值保留原报价字符串的最大十进制精度，只标注为“上游原始参考数值变化”，绝不解释为 CNY 成本变化。第一次观察、缺价、读取失败、映射/配置/结构/SKU 变化均记录明确结果并禁止计算差值；最新失败记录不会用旧报价填充。

配置或结构漂移会使用 ⑥-2C-2 既有检查将映射标为 stale，并记下本次不可用状态。页面会显示映射版本、连接配置版本、上游 SKU 组合、观察时间、币种/单位/扣费状态及可比性原因；若当前映射与保存该报价时的审核状态或版本不一致，历史报价会明确标记为不可代表当前报价。供应商协议夹具仍只允许账户查询、商品列表和商品详情读取。

## 人工内部成本与 ⑥-3A 定价交接

商品后台将成本输入标记为“人工确认成本（CNY/件）”。管理员编辑一个或多个 SKU 后必须先调用：

- `POST /api/v1/admin/products/:id/cost-preview`

预览按 SKU 展示旧/新成本、差额、现有成交售价和划线价、旧成本下毛利润/毛利率、新成本但售价不变时的毛利润/毛利率，以及当前规则对应的建议售价和该建议的毛利润/毛利率。手动模式只说明售价保持手动，不生成待执行的建议售价。缺成本、零成本、免费售价、负毛利润、金额精度、舍入、溢出及 SKU 状态沿用既有定价规则风险模型。

计算继续使用 `@aikayun/money` 的 Decimal.js 实现：`calculateUnitProfitMetrics` 与 `calculateSuggestedSalePriceDetailed`。报价比较另用 Decimal.js 精确计算原始参考数值差，不转换币种，不进入 `cost_price`。

成本确认复用既有 `PATCH /api/v1/admin/products/:id/prices/batch` / SKU 价格编辑权威路径。服务端核验预览摘要、商品与 SKU 修订、当前价格/成本和定价规则版本；成本变化必须与售价/划线价保存分开进行。多 SKU 请求在单一事务中验证并更新，任一 SKU 冲突、预览过期或摘要不匹配都会整批回滚。成功后只更新 `cost_price`，沿用既有价格审计和数据库修订；现有规则触发器按规则状态进入 stale。双提交或迟到请求凭旧修订失败，不会重复确认或覆盖新状态。

成本确认后如需调价，管理员必须单独打开 ⑥-3A 规则预览并再次明确确认应用。`manual` 模式不会生成必须执行的调价结果。顾客订单、支付、退款、履约、库存和已有幂等请求继续以原有订单行与不可变快照为准；本阶段只读检查订单金额，不回写历史交易。

## 验收与安全范围

API 使用真实 PostgreSQL 和受控卡易信 V3 HTTP 夹具；浏览器验收使用真实 Chromium。覆盖观察历史、未知币种/缺价/不可比状态、配置漂移、规格身份、权限/CSRF、公开顾客 API 不含报价、金额精度、成本预览与利润/毛利、固定利润/比例加价/手动模式、批量原子确认、并发竞争/旧摘要、规则 stale 后重新预览并确认、订单金额与幂等恢复以及桌面/移动端交互。

最终本地 `pnpm verify` 结果：金额单测 16/16；API/PostgreSQL 23 个测试文件、393/393；生产构建通过；主 Chromium 88/88；辅助浏览器 6/6（替代品牌 1、SSR 错误/安全 3、开发预览 1、生产品牌 1）。本地这些套件均无跳过和 flaky。Lint 0 error，保留 7 条未修改的顾客商品详情页面既存 warning。Nuxt Google Fonts 元数据请求超时，构建和浏览器套件均使用 provider fallback 并通过。

实现提交 `0a960eb978462f3d40a78e8b128aa54a94710036` 的 [GitHub Actions](https://github.com/YYKX682436/AiKayun/actions/runs/40379643370) 已完成并通过：金额 16 项、API/PostgreSQL 393 项、主 Chromium 88 项及辅助浏览器 6 项通过；Compose 浏览器 79 项通过、9 项跳过，跳过原因是外部 Compose 栈不包含隔离供应商夹具。Compose 重建持久化、隔离恢复、备份恢复和不可信 TLS 拒绝均通过。最终后续提交的 CI 状态以交付时的实际运行结果为准。

补充验证中发现：预览请求发出后修改草稿会使旧结果失效，但原加载状态未随旧请求结束而释放。现在分别跟踪请求归属与草稿代际；确认成本请求期间禁止关闭确认框或切换价格页，直至响应完成。缺成本或计算溢出时也不再误显示为手动模式。新增真实 Chromium 迟到响应回归，以及在真实 PostgreSQL 和受控只读 HTTP 夹具上切换连接、配置版本及上游 SKU 后的不可比较回归。各项最终验证数字和后续提交的 Actions 结果以交付回复记录。

## ⑥-3B 精准 R1：来源一致性

固定基线为 `ce5d943086bc7840d0bec98840e63bd319c3b926`。在真实 PostgreSQL 和受控卡易信 V3 只读 HTTP 夹具上，先暂停已审核来源 A 的详情响应，再由另一管理员切换并审核来源 B；基线回归观察到 `mapping_changed` 记录携带 B 连接、A 的上游 SKU 和 A 的 `15.00001` 报价。另两项基线红测分别证实 SKU 修订变化后 `sku_changed` 仍携带旧报价，以及同一映射修订变化后旧报价被拼到新修订上。三项回归在基线均失败。

根因是事务复核只改写 `attempt.outcome`，并可能将 `attempt.mapping` 替换为当前映射，却未同步清除旧读取数据。修复将请求开始时的映射快照与事务复核分开：只有来源、修订和结构均通过复核的成功/缺价读取保留本次读取上下文；失败记录保留请求时的真实来源快照和安全状态，报价为空，不能参与比较。加载映射时也重新核对请求的预期修订。页面对失败和缺价显示“本次没有可用报价”，区别各自的状态，不自动回退到上一条成功观察。

前向迁移 `202610270002_supplier_quote_source_consistency` 不更改或删除旧历史。旧版失败记录可能已经发生来源拼接，无法从该记录判定真实来源：接口隐藏其来源身份与报价并标记来源快照未确认，界面明确提示；旧版成功与缺价记录仍可读取。新记录标识经修复路径捕获的来源；`NOT VALID` 检查约束保留旧行，同时禁止新写入的失败记录携带报价或成功记录缺少报价。50 条上限和原有不可变保护不变。

真实 PostgreSQL 定向回归包含两位管理员、来源切换、SKU 和同映射修订竞争、失败后再次读取不可跨越失败记录比较、连接/配置/SKU/结构不可比、旧库迁移及不可变约束；既有同来源、缺价、权限、CSRF、密钥、历史、审计、公开接口及订单测试继续保留。Chromium 新增失败记录展示检查。`orders.spec.ts` 的复制成功断言限定在实际成功提示，仍检查剪贴板内容；没有改变交付业务。一次本地开发服务器定向运行中 Markdown 用例在进入商品页遇到 `ERR_ABORTED`，尚未运行到复制断言；其间发生开发服务器热重载，生产构建完整验证及最终 CI 结果以交付记录为准。

真实卡易信币种、报价单位、实际扣费、数量换算、`safePrice`、`outerNumber`、查单与图片提交语义，新订单购买资料归档真实 SIGKILL，以及在线生产数据库与私有卷一致性备份均继续为 **NOT_VERIFIED**。本轮不部署生产、不采购、不自动调价、不进入⑥-3C。
