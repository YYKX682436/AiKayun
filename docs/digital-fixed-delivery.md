# 固定文本与固定链接自动交付

阶段⑤-2在⑤-1订单与卡密池基础上增加 `fixed_content` 与 `link` 两种固定数字交付。它们复用同一 `orders`、`order_items`、库存预留/事件、履约尝试和交付历史，不建立第二套订单、库存或 worker。前向迁移为 `202610210004_fixed_delivery`；⑤-1迁移保持冻结。

## 数据模型与版本

每个 SKU 的 `product_variant_fulfillment` 仍只有一种当前 `method`。固定文本和链接的正文保存在 `product_variant_fulfillment_versions`：每条记录有 SKU、单调递增版本号、方法、加密正文、认证参数、密钥 ID、内容 HMAC 摘要、管理员和创建时间。数据库拒绝版本更新、删除和截断；当前配置用复合外键绑定同一 SKU 和方法的版本。`configuration_revision` 由 PostgreSQL 触发器控制，每次方法、当前版本或销售资格变化都递增。

保存内容只创建新版本并自动暂停新销售。商家必须另行明确启用。暂停销售只影响新报价，不改变已有订单。改履约方式、归档商品、退役 SKU 或商品复制不会重写订单快照：复制商品不复制交付配置、密文、版本或启用资格；旧订单仍通过自己的版本外键交付。

`order_items.fulfillment_content_version_id` 在原订单项行上记录成交时的版本；固定方法的数据库形状约束要求版本 ID，其他方式必须为空。订单项创建触发器会在同一事务内验证当前 SKU 方法、销售就绪状态和版本完全匹配。版本无法被覆盖或删除，历史版本可继续读取。

报价项与报价摘要包含 `configuration_revision` 和版本 ID。下单持有既有商品与 SKU 锁后重新报价；如果管理员先提交内容或销售资格变更，旧报价摘要冲突并返回新报价，不会静默改买新版本。若下单先取得锁，则订单绑定提交时仍有效的版本，管理员更新随后创建新版本。

## 加密与隐私

私有正文使用现有 `CODE_POOL_ENCRYPTION_KEY_RING` 中的 AES-256 密钥。代码通过用途标签 HMAC 派生独立的固定交付加密密钥与摘要密钥，不改变⑤-1卡密 AES 密钥、nonce、AAD 或密文格式。AES-256-GCM 使用 12 字节随机 nonce，16 字节认证 tag；版本 AAD 绑定 SKU、版本 ID 和方法，交付 AAD 绑定订单项、交付 ID、版本 ID 和方法。保存摘要为 HMAC，不记录可离线猜测的明文 SHA-256。

内容与链接私密数据都只以密文入库。后台私有配置和历史版本 API 设置 `Cache-Control: private, no-store` 并要求管理员身份；公开目录 API、商品 SSR 与 sitemap 不读取版本正文。订单正文只在服务端先验证本人顾客会话或有效游客会话、订单归属和成功履约记录后解密返回。顾客越权读取返回 404，其他身份不能读取游客内容。正文不进入日志、错误响应或审计备注。

密钥轮换时把新旧键同时保留在密钥环；所有历史版本和交付记录引用的 `encryption_key_id` 都必须继续存在。管理员启用销售时也会检查历史密钥是否齐全。旧密钥丢失时，顾客读取明确返回 `FIXED_DELIVERY_KEY_UNAVAILABLE`，worker 写失败尝试并等待恢复；认证失败返回 `FIXED_DELIVERY_DECRYPTION_FAILED`。系统不会用空内容伪造成功。不得修改⑤-1卡密池的密钥用途、密文上下文或 AAD。

URL 必须为完整 HTTPS 地址，不接受用户名/密码和控制字符，也拒绝 `javascript:`、`data:`、`file:` 等协议。服务器不抓取、不下载、不代理链接目标。Markdown 使用 HTML 禁用的解析器，链接只允许 HTTPS 或页内锚点；图片显示替代文字，不加载远端图片。顾客链接使用 `noopener noreferrer nofollow`，页面把访问说明作为文本编码显示。

## 自动履约与库存

原 `code-pool-delivery-worker` 已扩展为 `startDigitalDeliveryWorker`，统一处理 `code_pool`、`fixed_content` 和 `link`。API 实例启动立即扫描，之后每秒至多领取 20 个订单项；多个实例使用 `FOR UPDATE SKIP LOCKED` 分配任务。同一订单先锁订单行，再锁订单项、商品、SKU、数量库存（如有）和履约配置；尝试、逐件私有交付和成功转换在同一短 PostgreSQL 事务提交。进程在提交前退出时事务整体回滚，重启后的扫描会恢复仍待履约的 processing 订单。

worker 读取订单绑定的版本，不读取 SKU 当前版本。数量为 N 时，它创建 N 条各自加密的交付记录，并用原履约尝试成功触发器递增已交付数量和订单完成；重复处理不会重新履约成功项。失败尝试记录安全失败代码和有界指数退避时间，最多等待 5 分钟；确认付款的支付尝试和回执独立于 worker 事务，交付失败不会回滚收款。

- `quantity` SKU 仍在下单时创建唯一 `order_inventory_reservations` 与 `reserve` 事件。固定正文可重复售卖，不减少内容数量；每个订单单位成功履约时由原触发器写 `consume`，消耗真实数量库存。
- `unlimited` SKU 不创建数量预留，也不产生 reserve/consume 库存事件。每单位履约仍写入原订单项尝试和交付历史。
- 固定交付暂停或从 SKU 当前方法切换走，不取消任何已绑定版本的订单。退款不会清除已交付内容、恢复已消费库存或重新运行履约。

自动成功必须满足：订单 `processing`、零元订单或足额准时实收证据、没有未决支付尝试、没有开放服务商对账案例、数量库存账实正确（如适用）、交付记录数量与尝试数量一致。数据库触发器再次核验订单状态、支付证据、对账阻断、来源与版本绑定，阻止绕过 API 的 SQL 成功写入。

## 后台操作

在商品编辑页的“SKU 数字履约方式”选择人工交付、卡密池、固定文本或固定链接。固定文本编辑器提供 Markdown 输入和安全预览；链接编辑器要求 URL、标题，并可填写提取码/访问说明。页面显示当前版本、修订号、历史版本、冲突提示和历史订单保护说明。保存创建新版本并保持销售暂停；“明确启用自动交付”和“暂停新销售”是单独操作。只有商品/SKU 当前可售、库存为 `quantity` 或 `unlimited` 的数字 SKU 可以启用。

商品复制会创建草稿，并将所有复制 SKU 设为禁用；不会复制固定内容版本或自动履约资格。归档商品或永久退役 SKU 不删除历史版本、订单版本引用或已成功交付记录。

若保存响应提示履约修订冲突，页面保留本地输入；应重新查看当前版本和历史，再决定是否基于新修订重新保存。启用失败或服务端缺历史密钥时先恢复正确密钥，不能手工直接改数据库版本或就绪标记。

顾客订单详情显示自动交付进度、尝试失败后的安全提示、逐单位交付时间、Markdown/链接内容和复制操作。只有成功的履约尝试对应的交付行会返回正文。链接标题、HTTPS 地址和访问说明分别展示；游客继续使用原安全游客会话。页面使用私有 no-store 响应并在订单/身份切换时清除旧内容。

## 验收与运行

⑤-2需用真实 PostgreSQL 覆盖配置修订、旧报价失效、保存版本不可变、旧/新订单分别绑定并交付、Markdown 危险内容、危险链接协议、未付款隐藏、真实收款和零元履约、数量 N 库存消费、无限库存无数量事件、并发 worker、重启恢复、缺失/轮换密钥、顾客/游客隔离、公开目录脱敏、方式切换、归档/复制保护、退款历史保留及⑤-1卡密回归。浏览器必须实际从 SKU 编辑页保存并启用、完成结算，并在订单详情读取或复制交付。

本地完整验收命令为 `pnpm verify`，并需检查 Compose 全栈与 GitHub Actions 最终成功。测试库名必须以 `_test` 结尾且与开发/生产数据隔离；完成后仅清理本次创建的测试数据库、容器、媒体目录和临时输出。生产迁移、密钥初始化及阶段⑤-3不属于本阶段。
