# 阶段⑥-3A：精确定价规则与后台确认应用

## 范围

本阶段为每个 SKU 增加定价规则的配置、只读预览、管理员确认应用和审计历史。`product_variants.sale_price` 仍是唯一有效售价，`cost_price` 仍是管理员填写的内部单位成本；规则不会成为结算价格来源，也不会在保存规则时自动修改售价。

本阶段不重构商品、SKU、购物车、订单、填写模板或供应商映射。没有接入上游成本同步、成本变化跟随系数、定时调价或供应商采购。

## 定价公式与金额精度

每件建议售价的公式为：

| 模式 | 公式 | 说明 |
| --- | --- | --- |
| `manual` | 不计算建议售价 | 继续由现有管理员价格入口维护 `sale_price`。 |
| `fixed_profit` | `成本 + 每件固定利润` | 固定利润是对人工成本的加数，不是采购利润保证。 |
| `percentage_markup` | `成本 × (1 + 加价率 ÷ 100)` | 加价率按成本计算，不是按售价计算的毛利率。 |

计算使用 Decimal.js。成本和固定利润最多 13 位整数、5 位小数；加价率为百分数，最多 6 位整数、4 位小数，范围为 0–999999.9999。最终建议售价按 `ROUND_HALF_UP` 保留 2 位小数，并同时检查计算结果与最终售价能否落入数据库 `NUMERIC(18,5)` 边界。越界结果不可应用。

当前和建议毛利润以舍入后的售价减成本计算，并显示 5 位小数。毛利率按 `(售价 − 成本) ÷ 售价 × 100%` 计算，显示 4 位小数；售价为零时毛利率为空。预览明确区分按成本加价率和按售价计算的毛利率。

`cost_price = NULL` 表示成本缺失，不当作零。输入精度、金额上限、四舍五入到分或零价、负利润、停用/退役 SKU 和划线价冲突会作为风险显示。只有明确配置为零成本/零售价等情形才能得到零价；免费价或负利润必须在应用弹窗中再次明确确认。舍入不能悄悄生成零价。

## SKU 规则版本与状态

SKU 保存 `pricing_mode`、模式参数、`pricing_rule_revision` 和 `pricing_rule_status`。新增迁移 `202610260002_product_pricing_rules` 为已有数据添加 `manual` 默认值和修订号 0；不重算已有售价、成本或划线价。

每次实际更改模式或参数都会增加规则修订号，将策略状态设为 `pending`，并向 `product_variant_pricing_rule_versions` 追加不可变版本。恢复历史配置时复制配置为新的 `restored` 版本，并保留 `restored_from_revision`；旧版本不会被覆盖。相同配置重复保存不会生成空版本。

`manual` 表示无规则。`pending` 表示已有规则但尚未确认同步售价。成功应用后为 `applied`。对策略 SKU 直接更改售价或成本时，状态自动变为 `stale`，而不是声称售价仍与策略一致。手动售价仍能通过原价格管理入口修改，并记录 `price_updated` 管理审计。

规则版本保存和恢复只修改策略配置，不修改售价。策略应用记录 `rule_applied` 审计，独立保留应用前后的售价、成本、参数和输入摘要。管理审计与规则版本均保留管理员身份和创建时间。

## 预览、确认与并发保护

后台可逐 SKU 编辑策略，也可按本页批量保存；预览按勾选的 SKU 批量计算，包含当前售价、人工成本、规则及参数、建议售价、当前/建议毛利润与毛利率、售价差额和风险。预览只读，不更新商品。

确认弹窗要求管理员确认已检查批次内容；负利润或免费售价还需要额外确认。应用事务先锁商品，再按 SKU ID 排序锁定所有相关 SKU。事务重新核验商品修订、SKU 修订、规则修订以及覆盖计算输入的 SHA-256 摘要。任一 SKU 过期、退役、不可应用或摘要不匹配，整批拒绝；数据库事务保证不会部分成功。应用只更新权威 `sale_price` 和规则状态，不覆盖 `compare_at_price` 或 `cost_price`。

归档商品沿用现有禁改规则；永久退役 SKU 不可配置、恢复或重新定价。直接价格接口与规则应用遵循相同的商品→SKU 锁序。价格或成本的直接更改会使策略过期，因此两个入口不会互相覆盖并错误地显示已同步。

## 交易与历史边界

checkout 报价继续只读取 `sale_price`。售价更新后，依赖旧价格的报价 token 失效，顾客需要重新报价和确认；订单创建也继续重新检查当前报价。幂等 key 已命中的历史订单重放仍返回原订单金额。

本阶段不重新计算或改写已创建的订单项单价、订单总额、支付/退款、库存预留/消费流水、数字商品履约快照、`http_json_v1` 协议或供应商操作历史。

## 卡易信参考报价边界

卡易信 V3 `quote.amount` 仍是参考报价：其 currency 保持 `null`，`actualDebitVerified` 保持 `false`。本后台不把该值显示为已验证 CNY 采购成本，不换算未知数量，不自动写入 `cost_price`，也不由该值触发售价调整。⑥-3A 未向定价面板展示上游参考报价。人工输入的 CNY 成本仍不能改变上游实际扣费验证状态。

## 精准 R1：定价预览与编辑状态一致性

### 固定基线失败证据

R1 从 `553862ae122dd9410bb79f1c06793919d5297306` 开始。修改应用代码前，使用真实 Chromium、Fastify API 和隔离 PostgreSQL 18 在该基线复现：先保存 SKU 固定利润 `1`，确认 API 中规则为 `1.00000`；随后仅在页面把输入改为 `2` 并点预览。基线预览仍按服务器规则生成建议售价 `¥11.00`，确认应用弹窗仍可打开，风险确认后“确认并原子应用”按钮可用。该旧预览代表的正式规则与屏幕上未保存输入不一致。

### 根因与修复

- 预览流程没有拒绝脏规则草稿；参数编辑仅依靠 dirty 状态变化观察，dirty 已为 true 后再次输入不会再触发 false→true。现改为每次参数编辑递增输入代际并立即清除预览与确认状态；只要规则未保存，预览就明确提示先保存，服务端规范化规则返回后才可重新预览。
- 保存请求已捕获 SKU 编辑代际，但迟到成功响应未把捕获代际传入草稿合并函数，仍会覆盖请求期间的新输入。现只对请求期间未再次编辑的 SKU 合并服务器规范值；后续编辑原样保留并继续显示未保存。测试通过延迟真实 API 响应复现竞态，并确认数据库仍保存请求提交的旧值、界面保留新值。
- 规则保存与恢复都以服务端返回的规则项规范化非脏草稿。历史恢复成功后不再遗留旧草稿。规则读取和历史读取分别使用请求代际、商品 ID、SKU ID 校验；切换历史 SKU 会同步清空上一 SKU 的历史与恢复候选。预览同时绑定商品修订、页码、当前 SKU 选择和逐次输入代际。确认弹窗显示该预览中的 SKU、规则版本、参数及建议售价，并在提交前再次验证身份和版本。
- 父级商品页将定价规则脏状态纳入现有未保存提醒和价格分区状态，不改变其他分区的提醒机制。
