# 购物车与结算报价

> 现行购买行和购买资料状态请以[⑥-2B验收文档](./purchase-lines-6-2b.md)及[⑥-2C-1验收文档](./purchase-forms-6-2c-1.md)为准。本文件保留 ④-4/④-5 的基础购物车与报价说明；其中旧 SKU 主键、游客数据和支付提示已由后续阶段扩展。

阶段④-4提供登录顾客持久购物车、游客本地购物车及统一结算报价。阶段④-5在此基础上增加真实订单、基础库存预留、取消与超时关闭，以及人工数字交付；仍不接入支付渠道。订单事务与状态规则见[订单与人工交付](./orders-and-fulfillment.md)。

## 数据与身份

迁移 `202610190003_customer_cart` 新增：

- `customer_cart_items`：以 `(customer_id, sku_id)` 为主键，保存数量与创建/更新时间；数据库约束数量为 1～99。顾客外键在账户物理清理时级联删除。SKU 不设外键，让已删除商品仍能以不可用条目显示，也不阻止目录安全删除。
- `customer_cart_merge_requests`：以 `(customer_id, merge_id)` 为主键，保存规范化请求的 SHA-256 摘要和已跳过的未知 SKU。相同 ID、相同内容重放返回原合并结果；相同 ID 配不同内容返回冲突。

顾客身份只能由有效的顾客会话解析。每个读写事务会锁顾客行并重新检查顾客状态及会话有效性；禁用、删除、过期或撤销会话不能操作购物车。不同账户的条目不共享。顾客匿名化事务删除购物车与合并幂等记录。

游客数据只存在浏览器 `localStorage` 的 `aikayun-guest-cart-v2`。数据分成两种状态：`unclaimedItems` 是尚未认领的 SKU UUID 和数量；`pendingBatches` 是已经认领的不可变请求快照，每批保存原顾客 UUID、mergeId 和 SKU/数量。浏览器不保存价格、商品名称、库存、密码、Cookie、会话令牌或联系方式。顾客 UUID 只用于阻止已认领批次转交给其他账户。浏览器数据丢失不保证恢复。

登录顾客同步前，浏览器先用 Web Locks 串行化本地购物车读改写，把未认领商品写成绑定当前顾客的新批次，再发送请求。批次的 mergeId、归属和商品数量之后不再修改；网络错误、页面刷新、请求中断或结果未知时，批次保持原样。原顾客重新登录后以相同 mergeId 和请求体重放，服务端按 `(customer_id, merge_id)` 幂等返回；其他顾客不能提交该批次。批次认领后新加的商品留在 `unclaimedItems`，后续认领会生成独立 mergeId。成功响应只移除与该响应完全匹配的批次，不删除并发新增的未认领商品。若 localStorage 写入失败或浏览器没有 Web Locks，前端不发送无法安全恢复的合并请求。

注销后，已认领但未确认的批次仍保存在本机并继续绑定原顾客；它不会显示为访客商品，也不会显示给另一个登录顾客。其他账户可以读取和认领后来新增的未认领商品，原账户待确认批次保持隔离。共享 Cookie 的身份变更通过不含账户信息的本地修订标记通知其他标签页；认证变更使用跨标签独占锁，顾客请求在发送时使用共享锁并核对修订标记，旧标签发现身份已变化会先清空其顾客状态并重新读取服务端会话。购物车持久化和身份信号都不可用时，客户端拒绝自动合并。

前端认证状态为每次登录、退出、注册或顾客身份变化递增版本。认证变更在 Nuxt 应用内串行执行，并在浏览器标签页间使用 Web Locks 协调；其他写请求等待认证变更结束，并核对当前可读 CSRF Cookie 与请求 token 一致。购物车同步、报价和增删改操作在响应、错误及 `finally` 写回前都校验身份版本；过期响应不能覆盖当前账户的数据、错误、提示或加载状态。购物车状态由 Nuxt `useState` 在布局和页面间共享。切换身份会同步隐藏旧账户购物车并使已有同步 worker 转向最新身份；相同身份的重复初始化会合并到现有同步，不会重复认领同一批次。

上限为每个购物车 50 个不同 SKU，每个 SKU 数量为 1～99。报价和合并均接受最多 50 条输入；重复 SKU 按数量相加，合并后单个 SKU 超过 99 明确拒绝。登录顾客的并发变更先锁同一顾客行，新增/合并再按商品 UUID、SKU UUID 顺序锁目录行；主键约束提供最后一道去重保证。

## API

API 均使用 Fastify 路由及 `packages/contracts` TypeBox 契约。购物车和报价响应设置 `Cache-Control: no-store`。

| 方法与路径 | 用途 | 身份及保护 |
| --- | --- | --- |
| `GET /api/v1/customer/cart` | 读取登录顾客购物车并附当前报价 | 顾客会话 |
| `POST /api/v1/customer/cart/items` | 新增 SKU 或增加现有 SKU 数量 | 顾客会话、Origin、双提交 CSRF |
| `PATCH /api/v1/customer/cart/items/:id` | 设置数量 | 顾客会话、Origin、双提交 CSRF |
| `DELETE /api/v1/customer/cart/items/:id` | 删除一项 | 顾客会话、Origin、双提交 CSRF |
| `DELETE /api/v1/customer/cart` | 清空 | 顾客会话、Origin、双提交 CSRF |
| `POST /api/v1/customer/cart/merge` | 幂等合并本地游客购物车 | 顾客会话、Origin、双提交 CSRF |
| `POST /api/v1/checkout/quote` | 计算当前商品报价 | 可选顾客会话、Origin、双提交 CSRF；限流 |

请求中没有 `customerId`、单价、商品名或库存字段。顾客身份从服务器会话取得；报价输入只接受 SKU UUID 与数量。查询或修改其他账户购物车的路径不存在。

## 统一报价

购物车读取、商品详情的立即购买和结算预览都调用同一个报价服务。服务一次批量读取 SKU、商品、当前规格值、售价、库存配置/数量、已配置的履约方式与游客政策；不信任浏览器之前显示的金额、名称或库存。商品名称、规格、SKU 码和当前售价来自数据库。商品删除后的 SKU 以无效身份返回，数量不会被静默修正。

金额输入由数据库十进制文本读取，`packages/money` 仅接收十进制字符串。逐项执行当前单价 × 数量，再按 half-up 规则舍入为两位小数；小计在十进制域内相加。不会将金额转换为 JavaScript `number`。重复输入 SKU 先合并数量；数量非法、超限及金额溢出会返回明确的 4xx 错误，不会产生负价、零数量或重复结算金额。

报价包含 `quotedAt`、CNY、商品/SKU 身份、当前名称和规格、单价、数量、小计、可售库存、商品级与 SKU 级限购配置、登录顾客本人的有效购买数量/剩余额度、身份有效性、可否继续及不可继续原因。商品级数量会合并同一报价里的多个 SKU。游客看不到任何顾客历史数量；若账号累计或滚动 24 小时规则生效，报价返回 `login_required_for_purchase_limit`，提示“该商品需要登录后购买”并保留原结算意图。每单限制仍适用于游客。无法读取某条价格时 `totalAmount` 为 `null`，`pricedSubtotal` 仅合计可计价项，`totalComplete` 为 false；商品仍可显示。报价时间只是查询时间，不锁定价格或库存。

## 商品、库存和购买资格

资格判断依次检查：

1. SKU 与商品身份是否仍存在；商品是否为 `active`。
2. SKU 是否启用且未永久退役。
3. 当前规格组合是否仍通过阶段③共享的有效组合校验。
4. 库存模式是否已配置，以及该模式目前是否具备购买能力。
5. 当前购买数量是否不超过可信可售数量。
6. 已配置的履约方式是否存在真实执行能力。
7. 游客是否符合店铺策略。
8. 商品和 SKU 的每单、账号累计与滚动 24 小时规则是否全部满足。

订单创建事务会取得顾客行写锁后再复用该报价服务，并在目录、SKU 与库存锁内再次检查。订单报价失效、限购变化或额度被另一设备占用时返回新的服务端报价和明确原因，不创建订单、不预留库存。购物车不会预占额度；待付款及其他未安全关闭订单会在下一次报价中占用额度。限购口径、支付/退款/关闭的额度释放判定和异常资金保守处理详见[订单与购买限制](./orders-and-fulfillment.md#商品与-sku-购买限制)。

目前的库存规则：

- `quantity` 必须有对应库存行，且 `stocked - reserved` 不小于本次数量；无库存配置或库存不足会明确标记。
- `unlimited` 只表示不按数量扣减库存；不证明有交付能力。
- `resource_pool` 和 `external` 当前尚无对应资源提取或第三方同步能力，不能购买。
- `NULL` 表示库存模式未配置，不能购买。

当前购买填写资格读取 ⑥-2C-1 的 `preparing / active / paused` 状态和明确应用的冻结版本。`preparing` 不改变旧购买行为；`active` 下有模板 SKU 必须保存并校验当前模板资料；`paused` 阻止新的有模板购买订单，无模板 SKU 继续按原规则。准备关联需由管理员明确首次启用或保存并应用。详细转换、恢复、私有图片和订单归档规则见[⑥-2C-1验收](./purchase-forms-6-2c-1.md)。

`product_variant_fulfillment` 的方式名称本身不代表就绪。订单资格会复核当前商品、SKU、库存、顾客/游客策略及已配置履约能力。现有履约方法为 `manual / code_pool / fixed_content / link / file / api`；实际能力按该 SKU 的配置和对应履约服务判定。使用购买填写的自动履约 SKU，填写资料仍供人工按订单项处理；本阶段没有上游购买字段映射，也不把资料加入 `http_json_v1` 请求。

游客策略读取真实 `guest_checkout_enabled` 与 `guest_free_claim_enabled`：游客下单关闭时正价商品报价标记登录要求；免费商品按当前服务器价格单独检查免费领取开关。游客始终可浏览并维护浏览器购物车。登录顾客使用会话主体重新报价，不受游客策略影响。允许下单的游客由服务端自动签发 HttpOnly 会话 Cookie。当前 v2 请求按 `purchase-lines-6-2b.md` 保存稳定购买行、指定草稿和修订并复用既有幂等恢复；填写正文和图片不进 URL 或浏览器持久存储。

## 前台页面与阶段边界

- 商品详情支持选择有效 SKU、调整数量、加入购物车或立即购买。立即购买直接以 SKU/数量进入同一报价服务，不写入购物车。
- `/cart` 支持读取、增减、删除、清空、部分勾选及当前报价；游客展示本地购物车，登录顾客展示服务端购物车。
- `/checkout` 展示当前报价、商品异常原因及本次购买资料。创建订单时会重校报价和填写资格，并为数量库存创建预留；支付方式只以订单详情实际提供的选项为准，不据此宣称第三方渠道或供应商采购已验证。
- 导航显示购物车入口和数量；刷新及 SSR hydration 不输出游客或顾客价格数据到本地购物车存储。

报价本身不会写商品、SKU、库存修订、库存数量、订单、预留、资金、支付、履约或发货表。④-5与④-6不会把报价对象当作成交凭证，而是在加锁事务内重新读取商品、SKU、规格、售价、库存、履约、顾客/游客策略和购买限额；报价期间发生变化时返回新报价并要求顾客再次确认。
